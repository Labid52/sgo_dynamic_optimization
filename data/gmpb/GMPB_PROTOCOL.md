# GMPB dynamic-benchmark protocol (frozen before the final study)

External validation of the **Squid Game Optimizer** (SGO) of Azizi, Baghalzadeh
Shishehgarkhaneh, Basiri and Moehler, *Scientific Reports* **13**, 5373 (2023),
doi:10.1038/s41598-023-32465-z, on a recognized dynamic-optimization benchmark
that is independent of the MPC-generated sequences used elsewhere in this
project. GWO, PSO and WOA are controls whose only role is to separate
SGO-specific behaviour from general difficulty of the benchmark.

This document is committed **before** the final runs. Any later correction is
recorded in the report with its reason.

## 2. Integration method

MATLAB is not available in this environment and the Octave Forge `statistics`
package could not be built, so the integration is a **hybrid**:

* every environment sequence is produced by the **unmodified official Octave
  code** (`codes/gmpb_generate.sh` -> `results_v2/gmpb/octave/gmpb_dump.m`), and
  its complete state is written to a `.mat` file;
* `codes/gmpb_benchmark.py` **loads that official state** and reimplements only
  `fitness_GMPB.m` and the `fitness.m` FE/change/error bookkeeping, so the
  landscape itself is never regenerated in Python.

One library function is substituted: `pdist2`, which the official generator calls
once to normalise the shift vectors. The replacement in
`results_v2/gmpb/octave/shim/pdist2.m` implements the standard Euclidean
definition and is checked against its closed form. No GMPB source file is
modified.

### Equivalence gate (`codes/gmpb_equivalence.py`)

Must pass before any optimizer result is produced.

1. **Fitness**: official `fitness_GMPB.m` at 200 fixed probe points across 12
   environments, for several cases and seeds, against `GMPB.raw_fitness`.
2. **Run**: a deterministic optimizer-free query stream pushed through the
   official `fitness.m` wrapper in Octave, against `GMPB.evaluate`, comparing the
   per-evaluation objective values, the NaN pattern of the returned batch, the
   complete `CurrentError` trace, the `Ebbc` vector, the offline error, the final
   FE counter and the final environment counter.
3. **Shim**: `pdist2` against its closed form.

### SGO fidelity gate (`codes/gmpb_sgo_fidelity.py`)

The dynamic driver must be the published SGO. It is compared with the project's
`codes/sgo.py` (the implementation behind every manuscript result, reproducing
Azizi et al. on 11 of 13 published benchmark functions) on static objectives from
identical seeds, evaluation by evaluation, on both the evaluated points and their
objective values. Any change to an operator, or to the order in which random
numbers are drawn, would break this test.

## 3. Optimizers

SGO, GWO, PSO, WOA, taken from `codes/sgo.py`, `gwo.py`, `pso.py`, `woa.py`
without changing any operator. The vanilla SGO is the object of study; the other
three are controls.

| Setting | Value |
|---|---|
| Population size | **20 for every optimizer on every case.** No per-case tuning |
| PSO | inertia 0.9 -> 0.4, c1 = c2 = 2.0, velocity clamp 0.5 of the range |
| WOA | spiral constant b = 1.0 |
| GWO, SGO | no parameters beyond population size |
| Annealing schedules | GWO `a`, WOA `a` and `a2`, PSO `w` are indexed by progress through the **current environment** rather than by a global iteration count, identically for all three. SGO has no such schedule |

Higher fitness is better in GMPB; the drivers minimise `-fitness`, which is an
exact relabelling and leaves the published equations untouched.

## 4. Dynamic-state handling

One protocol for all four optimizers in the primary comparison, following the
EDOLAB template used by its own algorithms.

* The optimizer is **informed** of a change: the official wrapper sets
  `RecentChange` and refuses further evaluations until the algorithm clears it.
  No hidden change detector is used.
* On a change the algorithm clears the flag and **re-evaluates its retained
  population** under the new environment. Those re-evaluations **count against
  the budget**, as they do in the official `ChangeReaction_*` routines.
* The algorithm then continues with its own normal state: SGO keeps its
  population, best solution and offensive/defensive grouping machinery; GWO keeps
  its population and re-ranks alpha, beta and delta; PSO keeps positions,
  velocities and personal bests and re-evaluates the personal bests; WOA keeps
  its population and re-selects the leader.
* The true optimum is never given to any optimizer. No optimizer receives
  information the others do not.

## 5. Budget

The benchmark defines the budget. Every optimizer receives exactly
`ChangeFrequency` evaluations per environment and `ChangeFrequency x 100`
evaluations per run, with no exception and no import of the 1000-evaluation rule
used in the MPC study. Each run records its realized FE count, the number of
environments completed and the number of evaluations spent on post-change
re-evaluation.

## 6. Runs and seeds

* **31 independent runs** per case, per optimizer, per mode, as required by the
  competition.
* **100 environments** per run.
* The benchmark seed is the run index, exactly as EDOLAB does (`rng(RunCounter)`),
  so **run r presents the identical environment trajectory to every optimizer and
  every mode**. All comparisons are therefore paired by construction.
* The optimizer stream is seeded deterministically as
  `20260900 + 1000*run + 10*alg_offset + mode_offset`, so every run is
  reproducible.

## 7. Experiments

**Primary.** 12 cases x 4 optimizers x 31 runs = **1488 runs**, all under the
population-persistence protocol of section 4.

**SGO temporal-transfer diagnostic.** Four cases frozen here before any result is
seen: **F2** (baseline), **F8** (highest change frequency), **F10** (highest
dimension), **F12** (highest shift severity). Three modes, SGO only:

* **A, cold restart** - at every change, discard the population and initialise a
  fresh one with SGO's own initialisation;
* **B, previous-best seeded** - initialise a fresh population and replace one
  individual with the best solution of the previous environment, evaluated under
  the new environment before use;
* **C, population persistence** - retain the population, re-evaluate it, continue.

4 x 3 x 31 = **372 runs**. These are protocols for carrying information across a
change, not new SGO variants; no operator differs between them and SGO is not
tuned for any of them.

## 8. Metrics

**Primary, official.** Offline error
`E_o = mean(CurrentError)` over all `MaxEvals` evaluations, where `CurrentError`
is the best-so-far error inside the current environment, exactly as computed by
the official `fitness.m`. Reported per case as best, worst, mean, median and
standard deviation over the 31 runs, with all 31 raw values retained.

**Secondary, official.** `E_bbc = mean(Ebbc)`, the average best error immediately
before each change.

**Secondary diagnostics**, per environment and per run, all parameter free:
post-change error (best-so-far error at the first evaluation of the environment),
end-of-environment error, mean error, error reduction and its fraction, and
recovery evaluations to reach 50% and 90% of that environment's own error
reduction. Recovery is defined against each environment's own reduction because
the GMPB error scale varies by orders of magnitude across cases and no absolute
threshold can be fixed in advance without seeing outcomes. Population diversity
is recorded for SGO as the mean per-dimension standard deviation of the
population divided by the search range.

## 9. Statistics

* Wilcoxon signed-rank tests on the 31 paired runs, since the benchmark seed
  pairs the runs by construction.
* Holm correction inside each predeclared family: for the primary comparison the
  family is the three SGO-versus-control comparisons within a case; for the
  temporal diagnostic it is the three pairwise mode comparisons within a case.
* Cliff's delta with bootstrap 95% confidence intervals, 10\,000 resamples, the
  same effect size used in the manuscript.
* Median and interquartile range, plus mean and standard deviation because the
  competition reports them.
* Bootstrap 95% confidence intervals for paired median differences between
  temporal modes.

## 10. Validation gates

A, environments change at the expected evaluation counts; B, all optimizers see
identical environment trajectories for a given run index; C, optimum values track
the generated peaks; D, evaluation counters match the official rules; E, no run
exceeds its budget; F, no optimizer reads benchmark internals; G, SGO is the
Squid Game Optimizer and passes the fidelity gate; H, no Social Group
Optimization code is present; I, no per-case tuning; J, raw run counts equal this
protocol. Results are reported by `codes/gmpb_gates.py`.

## 11. Stop conditions

If the equivalence gate or the fidelity gate fails, the study stops and the
integration problem is reported instead of results. If a validation gate fails,
interpretation stops until the technical cause is fixed and the affected runs are
regenerated.
